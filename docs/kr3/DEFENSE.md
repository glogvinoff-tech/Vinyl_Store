# Сценарий защиты КР №3

1. Запустить `bash scripts/start-kr3.sh` (Windows — `scripts/start-kr3.ps1`). Показать три healthy контейнера и `/actuator/health` со статусом UP.
2. Открыть магазин. Показать четыре экрана макета: главная, каталог, альбом, корзина. Найти Radiohead, отсортировать по цене, перейти на следующую страницу.
3. Заранее выполнить OAuth-настройку Gmail по `README.md`. Зарегистрировать тестовый Gmail-адрес, получить письмо во входящих Gmail, подтвердить регистрацию. Выйти и войти по новому коду. Повторный код не работает.
4. Оформить заказ из корзины. Показать «Мои заказы» и уменьшившийся остаток пластинки. VIEWER не может редактировать служебные заказы.
5. Открыть `/admin.html`, войти bootstrap-администратором из `.env`, сменить временный пароль. Создать пользователей с VIEWER и MANAGER, показать разницу ролей.
6. В разделе «Заказы» создать заказ: номер DEFENSE-001, альбом Californication, исполнитель Red Hot Chili Peppers, покупатель, пластинка LP-001, дата, количество, сумма, NEW, оплата выключена, теги.
7. Изменить сумму на 14970 и включить оплату. Приоритет станет CRITICAL. В двух вкладках открыть один заказ и показать 409 при сохранении устаревшей версии.
8. Показать фильтры: `статус:оплачен`, `оплата:да`, `пластинка:LP-001`, `сумма>=5000`, `приоритет:критический`, `тег:доставка`, `архив:все`. Сортировать по сумме, названию и дате изменения; показать серверные `page/size/sort` в Network.
9. Архивировать заказ, найти через `архив:да`, восстановить. Удалить отдельный демонстрационный архивный заказ окончательно от ADMIN.
10. Добавить заметку, закрепить, изменить и удалить. Автор и дата сохраняются.
11. Выделить два заказа, выполнить SET_STATUS, ADD_TAG, ARCHIVE, RESTORE. Проверить число успешных операций и ошибки.
12. Импортировать `examples/orders.csv`: сначала preview, затем apply. Повторный CREATE_ONLY показывает ошибки существующих номеров; UPSERT_BY_EXTERNAL_ID обновляет. Добавить неверную строку и показать номер ошибки. Экспортировать текущий фильтр и открыть CSV.
13. Показать аналитику: всего, активные, архивные, оплаченные, средняя сумма, группировки.
14. Показать справочник: изменить цену/остаток, отключить пластинку (она исчезнет из публичного каталога), включить обратно. Изменения доступны ADMIN.
15. Показать пользователей: имя, email, роли, активность, временный пароль. Отключённый пользователь не входит.
16. Показать журнал аудита, поиск, сортировку и страницы, X-Correlation-ID запроса. Открыть Swagger после входа ADMIN.
17. Показать V0–V5, `flyway_schema_history`, таблицы и ограничения PostgreSQL. Объяснить отделение покупателей КР №1 от аккаунтов безопасности и перенос к UUID.
18. Выполнить `mvn -s backend/maven-settings.xml -f backend/pom.xml test`. Объяснить выбранный тест приоритета, фильтра, OTP или повреждённого CSV и быть готовым изменить бизнес-правило вживую.

## Вопросы по коду

- Почему нужны DTO: чтобы не отдавать JPA-граф, password_hash и серверные поля.
- Почему BCrypt: адаптивный хеш пароля с солью; код тоже хранится в виде хеша.
- Зачем refresh-сессия: access JWT короткий, длительное продление можно отозвать на сервере.
- Почему нельзя `SQL + input`: инъекции; поиск построен Criteria API, сортировка по белому списку.
- Как работает version: Hibernate сравнивает версию в UPDATE; устаревшие данные дают 409.
- Почему для UUID реализован Persistable: ID назначается до сохранения, `isNew()` позволяет JPA вызвать persist и вернуть актуальные timestamp/version.
- Почему OTP verification использует noRollbackFor: неверная попытка должна увеличивать счётчик даже при ответе 401.
- Почему checkout блокирует остаток: два пользователя не должны одновременно купить последнюю пластинку.
- Зачем Flyway: воспроизводимая история структуры БД, Hibernate только проверяет схему.

## Перед сдачей

Сохранить скриншоты экранов, healthy контейнеров, Swagger и тестов. Не прикладывать `.env`, реальные адреса/пароли отправителя, письма с рабочими кодами и данные личной базы. Приложить исходники, `.env.example`, инструкции, матрицу критериев и пример CSV. Отдельного требования к формату отчёта в предоставленном тексте нет.
