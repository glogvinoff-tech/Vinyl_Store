# Нейросеть рекомендаций SPIN

На главной странице появился блок **«В вашем ритме»**. Посетитель выбирает до восьми любимых жанров и получает три пластинки в наличии. Без выбора работает ознакомительная подборка. Жанры сохраняются в браузере отдельно для гостя и каждого аккаунта. Нейросеть не угадывает вкус неизвестного человека: для персонализации нужен его выбор.

## Запуск

В обычном Docker-запуске Python-сервис включён в `compose.kr3.yml`:

```powershell
docker compose --env-file .env -f compose.kr3.yml up -d --build --wait
```

Магазин: http://localhost:8080/ — блок расположен сразу после главного баннера. Python-порт наружу из Docker не публикуется. Дополнительные ключи API, GPU и внешние нейросетевые сервисы не нужны.

При локальном запуске без Docker установите Python 3.12+ и запустите отдельно:

```powershell
python -m pip install -r recommender/requirements.txt
python recommender/server.py
```

Затем запустите привычным способом Spring Boot и React. Для обновления фронтенда, который раздаёт Spring Boot:

```powershell
npm.cmd run build --prefix frontend
```

Java обращается к `http://127.0.0.1:8091`; другой адрес задаётся переменной `RECOMMENDATIONS_URL`. Python слушает только `127.0.0.1`; параметры — `RECOMMENDER_HOST`, `RECOMMENDER_PORT`. В Compose адрес уже настроен на `http://recommender:8091`. Недоступность помощника показывает сообщение и кнопку повтора только внутри его блока; каталог, корзина и заказы продолжают работать.

## Что именно обучается

Собственная небольшая нейросеть написана на Python + NumPy: **11 входов → 16 нейронов tanh → sigmoid**. В `neural.py` явно реализованы прямой проход, обратное распространение ошибки и обучение мини-пакетами. Это обучаемая модель с весами, не вызов ChatGPT и не сортировка по заранее заданным баллам.

`model.py` генерирует 4500 вымышленных событий для UUID текущих пластинок. Каждое содержит жанры посетителя, время, пластинку и количество: 0 — посмотрел, но не купил; 1–3 — купил. Из них 3600 используются для обучения, 900 — только для проверки. Количество купленных экземпляров увеличивает вес положительного примера в функции потерь. Seed `23112026` делает эксперимент воспроизводимым при неизменном каталоге.

Признаки: совпадение жанра, наличие выбранных предпочтений, вымышленная популярность пластинки, нормированная цена, скидка, циклическая связь жанра с месяцем, числом месяца и часом, выходной, конец месяца, вечер. Дата и время берутся на сервере по Москве (UTC+3), а не передаются пользователем. Открытая страница обновляет подборку при смене часа.

Первый запрос обучает модель в памяти. Следующие запросы используют готовые веса. Изменение состава каталога, жанра, цены или скидки вызывает переобучение; изменение остатка — только обновление доступных кандидатов. После перезапуска веса создаются заново из воспроизводимых данных. Синтетические события **никогда не записываются в таблицы заказов**.

Генератор задаёт учебные предположения о спросе: выбранный жанр повышает интерес, дата и время меняют его. Модель учится воспроизводить эти закономерности. Хорошее качество на синтетической проверке не доказывает полезность для реальных покупателей. Оценка модели используется для ранжирования; это не измеренная вероятность реальной покупки. Для настоящей персонализации в будущем нужен отдельный согласованный набор реальных событий и оценка на нём.

## Акции

Нейросеть ранжирует **уже действующие скидки**. Название подборки меняется по календарю: конец месяца, выходные, вечер, новогодний период. Выбор товаров зависит от предсказаний нейросети; названия задаются понятными календарными правилами. Новые скидки автоматически не записываются: расчёт заказа сохранён. Java берёт цену и размер скидки из базы магазина и проверяет наличие, независимо от ответа Python.

## Файлы и границы изменений

- `recommender/neural.py` — нейросеть и обучение.
- `recommender/model.py` — вымышленные покупки, признаки, кэш, подборки.
- `recommender/server.py` — внутренний HTTP API и проверка входных данных.
- `recommender/demo.py` — экспорт вымышленной истории для демонстрации.
- `backend/.../recommendation/` — новый контроллер и адаптер к Python. Существующие Java-классы не изменены.
- `frontend/src/features/recommendations/` — независимый React-блок, стили и настройки вкуса.
- В `HomePage.jsx` добавлены импорт и один компонент; в Compose — сервис и его адрес; скрипт архивации включает новую папку.

Схема базы, миграции, регистрация, авторизация, заказы, корзина, расчёт цены, консольная и JavaFX-версии не изменяются этим модулем. Python не получает имена, email, ID пользователей или реальные заказы.

## API и проверка

Публичный метод использует существующие правила доступа к каталогу:

```text
GET /api/catalog/recommendations?genres=Rock&genres=Jazz&limit=3
```

Ответ: `items`, `promotion`, `training`, `mode`, `dataSource: SYNTHETIC`, `generatedAt`, `timeZone`. Неверные параметры — 400, недоступный Python — 503. Пустой каталог — пустая подборка. Внутренний `POST /recommend` получает только метаданные каталога и выбранные жанры; `GET /health` проверяет запуск Python.

```powershell
python -m unittest discover -s recommender/tests -v
npm.cmd test --prefix frontend
.\mvn.cmd -s backend/maven-settings.xml -f backend/pom.xml test
```

Для Maven нужен JDK 21. Если он не найден автоматически, укажите `JAVA_HOME` на свою установку JDK.

Воспроизводимый экспорт без запущенного магазина:

```powershell
python recommender/demo.py --sample
```

Либо на текущем каталоге работающего магазина:

```powershell
python recommender/demo.py --shop http://127.0.0.1:8080
```

Результат — `exports/recommendations-demo.json`: каталог, все вымышленные события с количествами, пример рекомендаций и метрика проверки. Экспорт не импортируется в базу. Правила вымышленного спроса меняются в `generate_history`; размер сети и обучение — в `neural.py`.

### Выполненные проверки

Проверено 23 ноября 2026 года: 29 Java-тестов (включая существующие проверки магазина), 16 тестов фронтенда, 6 Python-тестов; production-сборка React и валидация конфигурации Compose прошли. Полный Docker-стек в рамках этой проверки не пересоздавался.

На демонстрационном каталоге из 24 пластинок: 944 вымышленные покупки, 1268 экземпляров; weighted BCE на 900 отложенных событиях — 0,3427 против 0,5676 у постоянного прогноза. Это метрика синтетического эксперимента, не точность рекомендаций для реальных людей.

Браузерная проверка использует работающую Python-модель, тестовый каталог и подменяет ответы магазина, не создавая реальных пользователей и заказов:

```powershell
npm.cmd run build --prefix frontend -- --outDir dist
node frontend/test/recommendations-browser.mjs
```

Нужны установленный Edge (либо `PLAYWRIGHT_CHANNEL=chrome`) и Python в PATH. При необходимости путь к интерпретатору задаётся через `RECOMMENDER_PYTHON`. Проверяются выбор жанра, сохранение после перезагрузки, разделение аккаунтов, мобильный блок, ошибка/повтор запроса и сохранение обычной подборки магазина. Скриншоты создаются в `.playwright/recommendations-desktop.png` и `.playwright/recommendations-mobile.png`. Обнаруженное переполнение существующего изображения вне нового блока не исправлялось, чтобы не менять прежнюю вёрстку.
