## Исправления после итоговой сверки: 9 ноября 2026 года

- Обе ошибки сначала воспроизведены новыми тестами: повреждённый CSV давал 500, событие экспорта отсутствовало в базе.

- Экспорт выполняется в транзакции с возможностью записи аудита. Проверяются единственное событие, автор, сохранённый фильтр и correlation ID; общая модель транзакций аудита изменений сохранена.
- Полный прогон в Docker / Java 21: **21 backend-тест, 0 ошибок**. `npm test --prefix frontend`: **9 тестов, 0 ошибок**. Production-сборка Docker проходит.
- На PostgreSQL через отдельный временный экземпляр подтверждены HTTP 400 повреждённого CSV и ровно одно событие `ORDER_CSV_EXPORTED` после экспорта. Повторно прошли CRUD/version, фильтры/сортировки/пагинация, справочник, заметки, все 5 массовых действий с частичным результатом, аналитика, пользователи, роли, временные пароли, аудит, Swagger, архив/восстановление/окончательное удаление.
- Созданные QA-записи и письма удалены. Основное приложение обновлено с сохранением базы и Gmail-настроек. Список реализации и подготовки к защите — [SUBMISSION_CHECKLIST.md](SUBMISSION_CHECKLIST.md).

- Frontend: `npm test --prefix frontend` — **9 тестов, 0 ошибок**. Проверены обновление JWT перед защищёнными действиями авторизации и отсутствие повторов при неверных учётных данных. Production-сборка Vite проходит.

Все сценарии прошли. QA-аккаунты, письма и временный контейнер удалены; основной экземпляр остался на Gmail SMTP.
