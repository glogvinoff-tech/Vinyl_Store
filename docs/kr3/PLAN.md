# План КР №3: SPIN / магазин виниловых пластинок

Предметная область КР №1–2 сохраняется. Основная сущность — заказ; связанный справочник — пластинка. Исходные консольное и JavaFX-приложения находятся в `src/`, новый сервер — в `backend/`. Копия примера Student Hub удалена после завершения адаптации: в сборке КР №3 она не используется.

1. Адаптировать Spring Boot backend под заказы магазина: UUID, номер, альбом, исполнитель, покупатель, email, телефон, дата, пластинка, количество, сумма, оплата, статус, теги, приоритет, архив, временные метки, версия.
2. Создать миграции Flyway, сохранить таблицы `users`, `vinyl`, `orders` КР №1 и переносить их данные в расширенную модель. Новые аккаунты безопасности отделить от прежних покупателей, у которых не было паролей.
3. Реализовать CRUD, безопасный поиск, числовые сравнения, сортировку, пагинацию, архив, восстановление, окончательное удаление администратором, заметки, массовые операции, CSV и аналитику.
4. Сохранить обязательную авторизацию по паролю: BCrypt, access JWT, refresh-сессии с ротацией и отзывом, роли VIEWER / MANAGER / ADMIN, смена временного пароля, блокировка перебора, аудит.
5. Реализовать индивидуальное задание: регистрация и вход с кодом на Gmail. Использовать Gmail API с OAuth2, одноразовый шестизначный код, хеш в БД, TTL, лимиты отправки и попыток.
6. Перенести главную, каталог, карточку и корзину из Figma в HTML/CSS/JS, подключить API, добавить избранное, личный кабинет и панель управления для защиты. Изображения хранить локально.
7. Обеспечить воспроизводимый запуск PostgreSQL, backend и тестового SMTP через Docker Compose, `.env.example`, генератор локальных секретов, healthcheck, Swagger.
8. Проверить бизнес-правила, поиск, безопасность и интеграционные сценарии, подготовить матрицу требований и сценарий защиты.

Проверки и ограничения фиксируются отдельно в `VERIFICATION.md`, чтобы отличать реализованный код от реально проверенных сценариев.

Сверка и исправления 9 ноября: все функциональные блоки плана представлены; обработка повреждённого CSV и сохранение события экспорта в аудит исправлены и покрыты тестами. Подробности — в [AUDIT.md](AUDIT.md), список требований и действий для защиты — в [SUBMISSION_CHECKLIST.md](SUBMISSION_CHECKLIST.md).

Обновление 5 ноября: фронтенд полностью перенесён из предоставленной версии VINYL_STORE-version_2.1 на React с подключением Spring Boot API, локальными шрифтами, анимациями и рабочим радио. Старые HTML/JS-страницы магазина заменены результатом сборки Vite; служебная панель КР сохранена.
